# 卡片機制衍生的特殊系統 — 設計參考文件

日期：2026-08-01
狀態：從真實卡片內容（預兆卡13張、道具卡12張、事件卡11張）歸納出的機制模式，作為 M2/M3 實作與**後續原創內容設計新機制時的參考**，避免每次遇到新卡片都重新發明一套做法。

本文件補充 [spec 文件](2026-07-31-web-multiplayer-design.md) 第 8 節的效果詞彙——spec 原本的詞彙（`stat_change`/`move`/`draw_card`/`dice_check`/`conditional`/`add_item`/`remove_item`）是設計時的合理猜測，實際卡片內容顯示需要更多機制模式，記錄於此。

## 核心架構調整：觸發時機系統（Trigger Hooks）

**這是最重要的一項發現**：spec 原本假設卡片效果是「抽到/進入房間時，立刻套用一次性效果」。但實際道具卡內容顯示，多數道具是「掛在某個時機點、由玩家自己選擇要不要用」的主動能力，不是被動一次性效果。

建議在 M2 核心引擎設計時，就加入一套「觸發時機」掛勾點，卡片效果註冊到對應時機，而不是只支援「立即套用」：

| 時機點 | 說明 | 範例卡片 |
|---|---|---|
| `onBeforeRoll` | 任何擲骰之前 | 天使羽毛（自選點數取代結果）、詭異人偶（多骰2顆，扣意志，每回合限1次） |
| `onAfterRoll` | 任何擲骰之後 | 幸運兔腳（重擲其中1顆，每回合限1次） |
| `onAttack` | 發動襲擊時 | 斧頭（+1骰）、獻祭之劍（+3骰+反噬風險）、左輪手槍（改速度襲擊、可打隔壁房間） |
| `onDamageTaken` | 受到傷害時 | 中世紀鎧甲（肉體傷害-1）、頭骨（精神傷害可改肉體傷害） |
| `onEventCardCheck` | 因事件卡需要考驗時 | 蠟燭（+1骰，情境限定，跟「攻擊限定」的斧頭不同） |
| `onOwnTurn` | 自己回合可主動使用 | 治療藥膏/嗅鹽（可對同房玩家使用）、魔術方塊（知識考驗換道具卡） |

**為什麼要現在就設計**：天使羽毛/詭異人偶/幸運兔腳這類「修改任意擲骰」的道具，不管是 M2 探索階段的房間考驗（塔橋、保險庫），還是 M3 之後的戰鬥擲骰，都要走同一套擲骰流程。如果現在只針對「探索考驗」設計，M3 加入戰鬥系統時就要回頭重做整條擲骰管線。**擲骰應該做成一個可插入修改器的管線（基礎擲骰 → 套用當前生效的修改器 → 比對門檻），不要當作單次函式呼叫。**

## 其他機制模式

### 1. 持有中被動加成（區別於一次性 `stat_change`）
拿到卡片時套用一次加成，卡片離手（被偷/給人/丟棄）時反向扣回，不是「抽到時扣一次」。
- 範例：書（知識+2/-2）、狗（力量+意志各+1/-1）、女孩（意志+知識各+1/-1）、聖符（意志+2/-2）、瘋漢（力量+2意志-2 / 力量-2意志+2，鏡像對稱）

### 2. 不可轉移旗標（`transferable: false`）
部分卡片明文「不可被偷竊/丟棄/轉交」，跟一般道具的自由交換規則不同。
- 範例：噬咬、狗、女孩、瘋漢（預兆卡）；中世紀鎧甲（道具卡）

### 3. 穿戴切換狀態（跟「持有」不同，是「持有中再切換裝備狀態」）
需要主動考驗才能切換「戴上/脫下」，兩種狀態各自有不同效果，且不是持有就生效。
- 範例：面具（知識+2/意志-2 戴上時；脫下時相反；考驗未過無法切換）

### 4. 牌堆偷看與重排
檢視牌堆（全部或最上面一張），可以選擇重新排列或洗牌後放置。跟單純的 `draw_card` 不同，不會真的抽走牌。
- 範例：水晶球（檢視道具/事件牌堆，選一張洗牌後放頂端）、通靈板（偷看房間牌堆最上面一張，選擇放回頂端或底部）

### 5. 消耗與使用次數
- **單次消耗**：用一次就消失（炸藥、治療藥膏、嗅鹽、天使羽毛）
- **隨機初始次數**：取得時隨機決定可用次數（左輪手槍，1~6次）
- **可重複使用但每回合限次**：不會消失，但每回合只能用一次（詭異人偶、幸運兔腳）
- **考驗成功才消耗**：魔術方塊（考驗成功才消失並換牌）、保險庫房間（同樣邏輯，考驗成功開啟）

### 6. 目標選擇（影響「自己以外」的對象）
之前所有效果都只影響使用者本人，這是第一批「可以選擇對同房間其他玩家生效」的機制。
- 範例：治療藥膏、嗅鹽（可選自己或同房間玩家）

### 7. 回復至基本值（區別於 `stat_change` 的加減）
不是「+N/-N」，而是「若低於角色基本值，直接回復到基本值」，效果量取決於角色卡設定，不是固定數字。
- 範例：治療藥膏（力量/速度回復基本值）、嗅鹽（知識/意志回復基本值）

### 8. 情境限定加骰（跟「無條件加骰」不同）
加骰效果只在特定情境觸發，不是任何擲骰都適用。
- 範例：蠟燭（只限事件卡考驗）、斧頭（只限力量襲擊）、獻祭之劍（只限力量襲擊，且伴隨反噬風險）

### 9. 範圍效果與目標免疫
效果影響「本房間+相鄰房間」的所有人物/怪物，且對特定類型目標無效。
- 範例：炸藥（範圍攻擊；對「無速度屬性」或「靈體怪物」免疫——代表怪物系統未來需要有「屬性類型」「靈體」這類標記）

### 10. 攻擊型態／傷害型態轉換
攻擊可以選擇用不同屬性發動（力量攻擊＝肉體傷害，意志攻擊＝精神傷害），且對特定目標無效；受到某種傷害時可以轉換成另一種。
- 範例：戒指（意志攻擊，對「無意志」目標無效）、頭骨（精神傷害可轉肉體傷害）
- 這代表怪物/實體需要有「是否具有意志」這類標記，供技能判斷是否生效

### 11. 反噬風險（攻擊本身附帶自傷分支）
攻擊加成的同時，伴隨一個對自己不利的考驗分支。
- 範例：獻祭之劍（+3骰攻擊，同時考驗知識：差則自傷，且本次攻擊視為無效）

### 12. 同房間全員效果（跟第6項的差異：不是「選一個目標」，是「同房間所有人都受影響」）
第6項（治療藥膏/嗅鹽）是「玩家選一個同房間對象生效」；這項是「同房間所有人都各自獨立進行考驗」，不用選擇目標。
- 範例：駭人尖叫（同房間內的所有人物各自以意志考驗）——原本記錄成「不分房間的全域效果」是誤植，開發者已確認實際範圍只限同房間

### 13. 玩家主動選擇考驗/加成的屬性
考驗用哪個屬性、或成功後加成哪個屬性，由玩家自己選，不是卡片固定指定。
- 範例：蜘蛛（選速度或意志考驗）、電話鈴聲（成功後任選一項屬性提升）

### 14. 附著於玩家的持續性卡片（依條件解除，不是依時間/回合）
卡片效果不是一次性結算就結束，會持續跟著玩家，直到滿足特定條件（不是「到下回合」這種時間條件）才解除。
- 範例：電池耗盡（限制只能移動到相鄰房間，直到玩家遇到其他玩家或身上有蠟燭才消失）

### 15. 附著於房間的持續性標記（影響該房間所有人的未來考驗）
跟第14項不同，這是標記釘在「房間」上，不是跟著某個玩家；之後任何人在這個房間做任何考驗都會受影響。
- 範例：滴答聲（房間內考驗-1骰）、祈禱聲（房間內考驗+1骰，最多8顆）
- 這代表房間需要能承載「持續性標記清單」，跟第4項的擲骰修改器管線是同一套機制的兩種掛載對象（掛在玩家身上 vs 掛在房間上）

### 16. 多階骰結果（3 段以上，不是單純成功/失敗二分）
`dice_check` 的 `success`/`failure` 二分法不夠用，需要支援 3 段以上的門檻分支。
- 範例：腐敗惡臭（≥5／1-4／0 三段不同效果）、水晶球（預兆卡，≥4／1-3／0 三段）

### 17. 不涉及屬性的純骰數判定
有些考驗不比對任何屬性，單純擲固定顆數骰子看點數範圍（本遊戲骰子為特製骰，每顆面值 0/0/0/1/1/2，非傳統 1-6 骰）。
- 範例：不起眼的櫃子（擲2顆骰，3-4成功/0-2失敗，無屬性關聯）

## ⚠️ 傷害系統是目前最大的缺口

「肉體損傷」「精神損傷」這兩個詞在事件卡/道具卡/預兆卡裡大量出現（腐敗惡臭、駭人尖叫、蜘蛛、濕滑的地板、天花板塌陷、炸藥、中世紀鎧甲、戒指、頭骨...），但我們還沒設計「受到 N 點傷害」實際會怎麼影響遊戲狀態——例如：
- 肉體損傷／精神損傷分別對應哪個/哪些屬性下降？下降多少？
- 屬性降到骷髏頭等級（最低）會發生什麼？
- 這個「傷害」的資料模型應該是獨立的效果類型（例如 `damage`，帶 `damageType: physical | mental`），而不是直接寫死某個 `stat_change`

這個缺口目前刻意不填，因為它牽涉到 M3 的整體戰鬥/傷害模型設計，建議 M3 詳細設計時第一件事就是把這個模型定案，之後所有牽涉到「損傷」的卡片效果都可以套用同一個模型，不用逐張卡各自決定。

## 一般性設計原則

**AI 主持人代勞原則**：實體版部分機制要求「另一位真人玩家代為執行」（例如噬咬要「前一位玩家代擲骰子」），這是因為現實遊玩沒有自動化主持人。**數位版不需要真的要求另一位玩家操作，由系統/AI 直接代為執行即可。** 之後設計任何原創機制，只要規則書寫著「請某某人代為...」，都套用這個原則轉換成系統代勞。

## M2 / M3 分工建議

- **M2（探索引擎）應該支援**：擲骰修改器管線（`onBeforeRoll`/`onAfterRoll`，可掛在玩家或房間上）、持有中被動加成、不可轉移旗標、穿戴切換狀態、牌堆偷看重排、消耗/使用次數系統、目標選擇（同房間指定對象／同房間全員）、回復至基本值、情境限定加骰（`onEventCardCheck`）、玩家主動選擇考驗屬性、附著於玩家/房間的持續性標記、多階骰結果、不涉及屬性的純骰數判定——因為這些在邪祟降臨前的探索階段就會用到
- **M3（邪祟降臨與戰鬥）應該支援**：`onAttack`/`onDamageTaken` 掛勾、傷害系統（肉體/精神損傷的資料模型，見上方缺口說明）、範圍攻擊與目標免疫、攻擊/傷害型態轉換、反噬風險機制——因為規則書明確寫「攻擊」是邪祟開始後才有的行動，這些機制的觸發時機都跟戰鬥綁在一起

## 使用方式

之後撰寫 M2/M3 實作計畫、或設計原創劇本的新卡片/道具/機制時，先檢查這份文件有沒有現成的模式可以套用，只有真的遇到全新模式時才需要再擴充這份文件。
