# 房間格局部縮放功能 設計文件

## 背景與目標
遊戲進行畫面（`DebugGameScreen.jsx` 的 `phase==='playing'`）目前允許瀏覽器原生雙指縮放整頁，這會跟畫面的 `position:fixed` 版面設計衝突（縮放後版面跑掉）。開發者希望：
1. 全域禁止瀏覽器原生縮放
2. 但視野區域中心的「當前房間格」（`--tile-size`，正方形視野的中心 70% 區塊）本身要能局部放大，方便玩家看清楚房間美術圖細節

## 核心機制

**全域鎖死原生縮放**：`client/index.html` 的 `<meta name="viewport">` 加上 `maximum-scale=1.0, user-scalable=no`。

**房間格獨立縮放狀態**：`FocusedRoomView.jsx` 新增 `zoomLevel` state（五段：100/125/150/175/200，數字，單位%），套用在房間圖片的 `<img>` 元素外層容器上，用 CSS `transform: scale(zoomLevel/100)`。這個縮放跟瀏覽器原生縮放完全脫鉤，只影響房間圖片本身，不影響鄰房預覽帶（15% 邊框）、四角動作按鈕、方向按鈕。

**縮放按鈕**：兩個小圖示（放大鏡＋號／放大鏡－號），浮在房間圖片內部右上角。
- `zoomLevel === 100`：只顯示放大鏡＋號
- `100 < zoomLevel < 200`：放大鏡＋號、－號都顯示
- `zoomLevel === 200`：只顯示放大鏡－號
- 每次點擊固定跳一級（100→125→150→175→200，或反向），不是連續縮放

**拖動查看四角**：`zoomLevel > 100` 時，房間圖片可以單指拖動（`touchstart`/`touchmove`/`touchend`，用 `translate()` 疊加在 `scale()` 之上）。拖動範圍限制在「圖片邊緣不能拖進房間格內側」，避免拖出空白區域。

**重置時機**：離開這間房間（移動到別的房間、或切到總覽地圖）時，`zoomLevel` 與拖動位移自動重置回 100%／置中，避免玩家回到同一間房卻卡在上次的縮放/拖動狀態。

## 範圍界定
這次只處理「聚焦房間視圖」（`FocusedRoomView.jsx`）裡的當前房間格。總覽地圖（`OverviewMap.jsx`）、鄰房預覽帶、四角/方向按鈕、狀態面板皆不受影響、不開放縮放。

## 測試重點
- 縮放按鈕的顯示/隱藏邊界（100%/125%~175%/200% 三種狀態）
- 拖動範圍限制（不能拖出空白）
- 離開房間時縮放狀態正確重置
- 全域原生縮放確認被鎖死（viewport meta 設定）
