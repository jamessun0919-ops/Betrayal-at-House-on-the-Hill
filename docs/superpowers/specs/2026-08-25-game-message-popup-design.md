# 遊戲訊息彈窗流程與機制 設計文件

## 背景與目標

目前房間進入、事件/預兆觸發等遊戲事件只會寫進一個沒有畫面顯示的除錯用文字陣列（`messages`，自 2026-08-19 改版後從未被渲染），玩家完全看不到這些資訊。既有的 `pendingCheckQueue`／`CheckModal` 已經是一套可運作的「排隊、依序彈窗」機制，但目前只服務房間離開/倒塌考驗與有骰子考驗的抽卡，考驗過程的擲骰動畫是 2500ms 純文字佔位，結果畫面顯示的是通用「OO考驗擲出N點，成功/失敗」文字，沒有使用卡片本身的敘事文字（`feedbacktextDice`/`feedbacktextOccur`，2026-08-22 已加入資料但目前完全沒有程式碼讀取）。

這次設計把「房間進入」「事件/預兆觸發」「道具使用結果」都納入同一套彈窗排隊機制，並把考驗結果畫面換成卡片本身的敘事文字。

**範圍**：只涵蓋開發者原始需求的第 1 節（房間/事件彈窗）與第 2 節（道具使用彈窗）。第 3 節（襲擊）與第 4 節（受到襲擊）**不在本次設計與實作範圍內**，僅在本文件末尾原樣記錄流程，留待 M3 階段實作。

## 整體架構

擴充現有的 `pendingCheckQueue`（`DebugGameScreen.jsx`）與 `CheckModal.jsx`，讓佇列項目從「只有考驗」擴充成 6 種類型，全部共用同一個先進先出佇列、一次只顯示一個：

| 種類 | 觸發時機 | 內容來源 | 顯示型態 |
|---|---|---|---|
| `roomIntro` | 玩家第一次進入房間，僅推給實際移動進入的那位玩家 | 房間 `name`／`description` | 單畫面＋確定鈕 |
| `eventIntro` | 抽到事件/預兆卡 | 卡片 `description` | 單畫面＋確定鈕 |
| `eventNoCheck` | 事件/預兆卡沒有骰子考驗（`eventIntro` 之後直接接） | 卡片 `feedbacktextOccur`（缺欄位顯示「待補充」） | 單畫面＋確定鈕 |
| `leaveCheck`／`collapseCheck` | 房間離開/倒塌考驗（既有，不變） | 房間資料 | `'before'→'animating'→'result'` 三階段，結果沿用現有通用文字 |
| `cardCheck` | 道具/事件/預兆的骰子考驗（既有，結果畫面改版） | 卡片 `text`（考驗說明）＋結果改用 `feedbacktextDice`（缺欄位顯示「待補充」） | `'before'→'animating'→'result'` 三階段 |
| `itemUseResolved` | 點擊道具「使用」且沒有觸發骰子考驗 | 卡片 `feedbacktextOccur`（缺欄位顯示「待補充」） | 單畫面＋確定鈕 |

考驗類（`leaveCheck`/`collapseCheck`/`cardCheck`）的 `'animating'` 階段統一從目前的 2500ms 純文字佔位換成播放 `ROLLDICE.mp4`；純展示類（`roomIntro`/`eventIntro`/`eventNoCheck`/`itemUseResolved`）只有單一畫面＋確定鈕，不經過擲骰動畫。

`messages` 陣列維持現狀不動，彈窗是新增的獨立顯示層，不依賴、也不取代它。

## 1. 房間/事件彈窗

### 1-A 房間進入彈窗

`game:roomEntered` 目前廣播給整個遊戲場次的所有玩家（`io.to(roomCode).emit`），不分是誰移動、也不分該玩家是否第一次進入。這次改成：伺服器判斷「這是否為該玩家第一次進入此房間」（用既有的玩家已訪問房間紀錄），只有第一次進入時，才額外對**該玩家本人**（定向送達，比照 `pendingInventoryChoice` 用 `data.playerId !== playerId` 過濾的既有寫法）推一個 `roomIntro` 佇列項目，內容是房間 `name`／`description`。非第一次進入、或該房間本來就沒有 `description`（目前 52/52 房間都有，理論上不會發生）則不推播。

### 1-B 事件/預兆觸發彈窗

抽到事件/預兆卡時（`game:cardDrawn` 已有 `deckType` 可判斷），推一個 `eventIntro` 佇列項目，顯示卡片 `description`。

**無骰子考驗的簡化路徑**：如果這張卡沒有 `dice_check` 效果，`eventIntro` 彈窗確定後，直接接一個 `eventNoCheck` 佇列項目，顯示該卡的 `feedbacktextOccur`（沒有這個欄位就顯示「待補充」，目前所有預兆卡都會落在這個情況，因為預兆卡尚未補上此欄位）。

**有骰子考驗**：`eventIntro` 彈窗確定後，直接接現有的 1-C/1-D/1-E 考驗流程（`cardCheck`），不需要額外的種類。

### 1-C 考驗內容彈窗

沿用現有 `CheckModal` 的 `'before'` phase，不需要新邏輯——已經會顯示 `source.text`。

### 1-D 擲骰動畫

`'animating'` phase 從目前 2500ms 純文字佔位換成播放 `ROLLDICE.mp4`（複製到 `client/public/videos/roll-dice.mp4`，單向複製，開發者之後換片只需重新複製覆蓋）。影片播放結束（`onEnded`）自動進入 `'result'` phase；保留「跳過」按鈕直接切換過去——因為考驗結果（`rolled`/`passed`）在佇列項目建立當下就已經是伺服器算好的，影片單純是節奏延遲，跳過不影響正確性。

### 1-E 考驗結果彈窗

`'result'` phase 改成依來源分流：

- 來源是**卡片**（item／event／omen）：伺服器在組 `game:checkResolved` payload 時，用擲骰結果 `rolled` 比對該卡 `feedbacktextDice` 的鍵值範圍（鍵值格式為 `"N+"`／`"A-B"`／`"N"`，跟卡片 `effects` 內 `dice_check.tiers` 的 `{min,max}` 一一對應，例如 `"5+"` 對應 `{min:5,max:8}`），找出對應文字一併送給前端。找不到欄位或找不到對應鍵值 → 顯示「待補充」。這個比對邏輯放在**伺服器端**，前端不重複維護卡片查找邏輯。
- 來源是**房間**（`leaveCheck`／`collapseCheck`）：房間資料沒有、也不會有 `feedbacktextDice` 欄位，維持現有通用「OO考驗擲出N點（需要N以上），成功／失敗」文字，不套用「待補充」規則。

## 2. 道具使用彈窗

### 2-A 選單本身

現有選單（`CharacterPanel.jsx`，剛完成的道具手持/配戴機制）已經是「依 category 動態決定選項」——武器手持/取下、裝備配戴/取下、消耗品/重複使用品「使用」——選項邏輯完全不動。唯一缺口：目前彈窗只顯示卡名，沒有顯示 `description`，這次新增一行 `description` 顯示。

### 2-B 點擊使用

**技術決策**：伺服器端「使用道具」跟「抽事件/預兆卡」共用同一個 `handleEffectResolveResult` 函式，這個函式最後一定會廣播 `game:effectResolved`（不管有沒有骰子考驗都會發），同時也被「骰子介入選擇」「道具二選一等待」「房間搜索加成」等其他非『點擊使用』的情境共用，不適合直接拿來精準觸發彈窗。

因此**不修改這個共用函式**，改在「道具使用」動作處理的源頭（`socketHandlers.js` 的 `mode === 'use'` 分支）額外發一個專用事件 `game:itemUseResolved`，只在「這次使用沒有觸發骰子考驗」時發送，內容包含伺服器查好的 `feedbacktextOccur` 文字（缺欄位顯示「待補充」）。前端收到後推一個 `itemUseResolved` 佇列項目。如果這次使用**有**觸發骰子考驗，就不發這個專用事件，改走 1-C/1-D/1-E 的 `cardCheck` 流程（`feedbacktextDice`）。

道具本身的 `effects`（如 `grant_item`/`stat_change` 等）維持既有的伺服器端執行邏輯不變，這次只新增「執行完之後彈窗顯示結果文字」這一層。

### 2-C 遺留

現有 `handleLeaveItem` 已經是「物品從背包移到房間地板清單」，完全符合，不需要改動。

### 2-D 給予

現有「給予」子選單已經是「從房間內玩家清單選擇目標，選定後移動到對方背包」，`roommates` 已經是同房間玩家的過濾清單，完全符合，不需要改動。

## 附錄：襲擊/反擊流程記錄（M3 階段實作，本次不展開）

以下為開發者原始需求，原樣保留供未來 M3 階段實作參考：

### 3. 襲擊

1. 選擇目標，從房間角色清單中選擇
2. 彈出能力考驗，根據自身裝備武器，顯示目標能力與自身能力，點擊確定或點視窗外關閉
3. 連結擲骰動畫
4. 彈窗顯示考驗結果：
   - 襲擊失敗：顯示自身受到傷害點數，根據肉體或精神傷害，跳出當前對應能力數值與級別條，選擇要下降的能力，重複直到傷害扣完
   - 襲擊成功：彈出目標受傷點數與種類，不顯示對方如何分配

### 4. 受到襲擊

1. 彈出訊息顯示受到誰襲擊
2. 彈出能力考驗，顯示目標能力與自身能力，點擊確定或點視窗外關閉
3. 連結擲骰動畫
4. 受到襲擊成功：顯示自身受到傷害點數，根據肉體或精神傷害，跳出當前對應能力數值與級別條，選擇要下降的能力，重複直到傷害扣完
5. 敵方襲擊失敗：顯示反擊成功，彈出目標受傷點數，不顯示對方如何分配
