# 房間資料填寫說明

`rooms.json` 放 MVP 測試版會用到的 18 個房間磚資料。

## 欄位格式

```json
{
  "id": "room_chapel",
  "name": "禮拜堂",
  "floor": "ground",
  "drawType": "",
  "text": "若在此房結束回合，可獲得1級神志。每位探險者在遊戲中只能受益於此房一次。",
  "effects": [
    { "type": "stat_change", "stat": "sanity", "delta": 1, "onceOnlyPerPlayer": true }
  ],
  "needsCustomLogic": false
}
```

- `floor`：`"ground"`（一樓）/ `"upper"`（二樓）/ `"any"`（一二樓皆可，依開發者確認的通用房間規則）
- `drawType`：**目前全部是空字串，需要你對照實體房間磚補上**——每張房間磚背面通常會標示走進這間房要抽哪一種牌（`"event"`/`"item"`/`"omen"`），麻煩對照實體元件填入；如果這間房沒有標示要抽牌（有些房間單純只是空間，不觸發抽牌），就填 `"none"`
- `text` / `effects`：跟 `data/cards/README.md` 的格式一樣。已經從規則書查到的 4 個房間效果（禮拜堂/圖書室/食品儲藏室/塔橋）已經先填好，其餘 14 個房間規則書沒有列出特殊效果（代表是純粹的普通房間，不用特別填 `effects`，除非你對照實體房間磚發現有些微文字說明忘了收錄進來）
- `needsCustomLogic`：塔橋（雙側阻擋、需力量檢定才能通過另一側）這種不是單純「屬性增減」的機制，标記為 `true`，`effects` 留空，之後跟開發者一起討論怎麼實作

## 樓層分配說明（附加背景，非資料本身需要的欄位）

這 18 個房間裡，6 個是劇本1/10 直接需要的，12 個是額外增加隨機性用的。樓層判斷大多是低信心猜測（因為規則書沒有完整的樓層對照表），其中 7 個房間（廚房/廢棄的房間/食品儲藏室/臥房/傭人房/焦黑的房間/染血的房間）依開發者確認，遊戲機制上是「一二樓皆可」的通用房間磚。若之後發現有房間的樓層猜錯，直接改 `floor` 欄位即可。

刻意排除的地下室相關房間（因為 MVP 測試版不含地下室）：地下湖、地底深淵、地下墓穴、來自地下室的樓梯、酒窖。
