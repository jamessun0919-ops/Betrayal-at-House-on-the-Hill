# 角色資料填寫說明

`characters.json` 放可選角色的資料，目前是**6 個空白佔位範本**（對應遊戲畫面預留的 6 個選角色位置），請陸續對照實體角色卡把內容填進去。填完之後 M2b/M2c 會直接讀取使用；填之前，選角色畫面上這 6 個位置都會顯示同一套測試假數值，不影響開發進度。

## 欄位格式

```json
{
  "id": "char_001",
  "codename": "",
  "gender": "",
  "age": null,
  "occupation": "",
  "stats": {
    "might": { "track": [], "baseIndex": 0, "skullIndex": 0 },
    "speed": { "track": [], "baseIndex": 0, "skullIndex": 0 },
    "knowledge": { "track": [], "baseIndex": 0, "skullIndex": 0 },
    "sanity": { "track": [], "baseIndex": 0, "skullIndex": 0 }
  }
}
```

- `id`：依序編號即可（`char_001`、`char_002`...），不要重複
- `codename`：角色卡上的代號/名稱
- `gender`：性別
- `age`：年齡（數字）
- `occupation`：職業
- `stats`：四項屬性（力量 `might`／速度 `speed`／知識 `knowledge`／意志 `sanity`），**每一項都是一整排刻度，不是單一數字**——這是實體遊戲角色卡的真實機制，跟一般 RPG 遊戲不一樣：
  - `track`：從角色卡上**由左到右、依序**把每一格刻度的數字抄進陣列，例如角色卡力量那排寫著 `3 3 4 5 6 6 7 7 7 8`，就填 `"track": [3,3,4,5,6,6,7,7,7,8]`
    - **必須是「由小到大或相等」（非嚴格遞增，允許重複數字）**，系統會檢查這件事，順序不對或有下降會直接報錯
    - 玩家角色的「目前這格刻度」（用陣列的索引表示，不是刻度上的數字）會隨遊戲進行上下移動；上升/下降一級＝索引加/減一格，**不是刻度數字加/減一**，因為刻度可能有重複數字，移動一格不一定會改變實際數值——這是判斷玩家「扣屬性扣得划不划算」的關鍵，UI 顯示要用長條圖+刻度來呈現這個機制，不能簡化成單一數字
  - `baseIndex`：角色卡上標示的**起始刻度位置**（陣列索引，從 0 開始算），開局時玩家會站在這一格
  - `skullIndex`：角色卡上骷髏頭圖示標示的那一格刻度（陣列索引），代表這項屬性的最低下限——邪祟開始前，玩家最低只能降到 `skullIndex + 1` 那一格；邪祟開始後才可以真正降到 `skullIndex` 那一格

## 範例

假設某角色的力量刻度卡面是：`3 3 4 5 6 6 7 7 7 8`（共 10 格，索引 0~9），起始位置在第 5 格（索引 4，數值 6），骷髏頭畫在最左邊第 1 格（索引 0）：

```json
"might": { "track": [3, 3, 4, 5, 6, 6, 7, 7, 7, 8], "baseIndex": 4, "skullIndex": 0 }
```

## 填寫前的注意事項

- 目前 `server/src/game/playerEntity.js` 已經改成刻度制，`data/characters/characters.json` 填完後可以直接對接，不用再等程式修改
- 在真實角色資料填完之前，M2b/M2c 的開發與測試會先用測試用的假刻度資料跑（不會等這份檔案），填完之後再切換成真實資料，不影響開發進度
- 每個角色四項屬性刻度的**長度不用一樣**（不同角色可能力量刻度有 8 格、速度刻度有 10 格），系統不限制長度，只檢查「非遞減」
